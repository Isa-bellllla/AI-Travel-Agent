# Update 4：字段与主体相关性、澄清答案的使用

本版继续修改 Agent 及其 LLM 结构化提示/工具契约，没有微调模型权重。

- 偏好增加 target_field、normalized_value、evidence_scope。category 对应 CSV Brand level；品牌、国家、城市各自绑定来源字段。结构化字段的证据由程序直接比较该字段，不能用标签/描述中的同词替代。无法映射的等级保持未解决，不会在自由文本里寻找 luxury 作为替代。
- 语义证据必须声明 hotel_property / hotel_location_relation / other_entity / unclear。设施偏好需要酒店自身属性证据；位置关系需求需要相应关系证据。领域字段正确性与字符串出处分别校验。关系和蕴含判断仍由 LLM 完成，需要真实模型审核；引用确实存在并不单独证明语义正确。
- 澄清记忆保存 topic、target_slot、preference_keys、问题、用户答案、标准化值、pending/answered/skipped、提问与解决轮次。确认后的槽位更新和偏好确认会解除对应不确定性。旧等级的暂定备选会被新的已确认等级替换。
- 当规划输出仍重复一个已解决问题时，执行层根据有效的澄清记忆过滤该重复问题，继续推荐。相同字段的不同 topic 名称也可关联。清空答案、新的冲突或新偏好仍允许必要澄清。若只缺目的地，问目的地，而不是继续问已经确认的等级。
- 如果用户已经明确要豪华等级且目的地明确，应直接查询，不强迫先选“连锁还是豪华品牌”。两者不是天然互斥属性。若用户确实在澄清“等级而非特定品牌”，应更新 category 并按意思清除不再需要的 brand 限制。

本数据实际等级是 high-end、Top Luxury、International chain 或空白，没有字面值 luxury brand。当用户明确指豪华酒店等级时，LLM 将表达标准化为 Top Luxury；程序执行实际字段查询，输出仍显示来源等级。

对应 rubric：A 检查事实与来源；B 检查正确识别概念、所有可验证硬条件与具体理由；C 检查必要且准确的澄清、清楚时直接执行、吸收后续答案。词向量相似度和关键词覆盖度不能替代这些判定，也不能当作 >=80% 的偏好识别率。

记录运行 75 个自动测试通过。新增测试包括：邻近豪华酒店不能证明本酒店等级；描述中的其他品牌不能证明自身品牌；相邻设施不能当作酒店设施；全部结构化字段的交叉污染；等级澄清后的连续查询；有旧重复问题时仍使用答案；仅追问缺失目的地；确认语义解释；清空答案、新冲突和同字段 topic 变体。

测试是程序与结构化输出契约的回归，不是实际 API 模型的语言泛化分数。仍需在用户环境中使用真实模型运行并按原 rubric 审核。网页会话内保存历史与结构化状态；未增加跨重启账户记忆。

使用方式不变：停止旧网站，从新版目录打开 Start_Travel_Agent.ipynb，配置自己的 API 模型与密钥并启动新网站，使用 New Conversation 测试。旧目录及密钥文件不会被 ZIP 覆盖；建议解压到新目录保留旧版本备份。
