# Architecture and implementation phases

1. **Audit:** stdlib CSV/ZIP/XML inspection; reproducible `scripts/audit.py`; original files unchanged. See schema report for actual columns and missing values.
2. **Database tools:** immutable source records in a read-only, in-memory SQLite database. Pydantic allowlists filter fields, operators, operations, sort fields, and grouping. All values are bound parameters. No model-generated SQL or Python is executed. Tests compare actual database outputs with independent source-row calculations.
3. **Hybrid retrieval:** structured filters first; TF-IDF plus cached optional local neural embeddings or deterministic LSA; label overlap and budget fit; final source-evidence reranking. Semantic retrieval ranks candidates and cannot prove amenities. The fallback is openly described as a statistical baseline.
4. **LLM interpretation/clarification:** provider-independent structured generation produces typed plans. The prompt dynamically reasons about material ambiguity, broad experience before amenities, explicit versus subjective budgets, and missing destinations. No hardcoded example responses or keyword intent routes. Invalid model output gets one schema repair attempt, then fails safely. Local inference is the default; paid calls require explicit opt-in.
5. **Memory:** structured slots, preference deltas keyed by semantic concept, confidence, hard/soft status, confirmation, negation, priority, and source turn. Entire active history, latest ordered hotel list, comparison/detail focus, pending question, and last query result are preserved. Updates run transactionally on a deep copy; model or tool failures do not mutate the active session. Streamlit isolates sessions; new conversation resets state. Context-window overflow is an explicit limitation rather than silent history truncation.
6. **Grounded generation:** the LLM selects evidence field/quote/preference triples; deterministic checks reject unknown IDs and quotes not literally present in the corresponding row. Hard semantic matches require verified evidence. The response renderer uses source-backed cards with prices, personalized evidence, budget fit, seasonal notes, and unknown/trade-off notices. Free-form LLM prose is not used to introduce new hotel facts. Entailment/relevance of a quoted passage is still a model judgment, not mathematically proven.
7. **General QA:** read-only count, list, detail, sorting, grouping, aggregates, comparisons, seasonal absolute/percentage changes, and similar-but-cheaper retrieval. Simple counts bypass recommendations and evidence generation. Queries about earlier hotels resolve IDs before execution. Detail/compare focus preserves the shortlist order for later ordinal references. Semantic aggregates must cover all structured candidates; they refuse an incomplete whole-database calculation above the review limit.
8. **Streamlit:** homepage, call-to-action, persistent per-session chat, recommendation cards, reference prices, loading/error states, new conversation. Developer configuration and evaluation stay outside the UI. No paid fallback on connection failure.
9. **Evaluation:** frozen development, held-out, and acceptance scenarios, actual-model runner with detailed traces, human-annotated A/B/C scores, official aggregate formulas, deterministic database benchmarks, and contract regression tests. Live-model and held-out quality evaluation remain blocked by unavailable inference. No synthetic score substitutes for them.
10. **Delivery:** README, version-pinned environment, configuration example, reports, regression tests, input data/rubric, and source ZIP. The source archive excludes credentials, caches, virtualenv, and Git metadata.

## Boundaries and trade-offs

A three-B model is a reasonable CPU development starting point, not a validated quality choice. Local Qwen and Ollama are swappable through the JSON provider interface. The interpreter sees location vocabulary and actual schema; it never receives a fictional database schema. User text and records are treated as untrusted data in model prompts. Exact quote validation, safe Markdown rendering, allowlisted tools, read-only storage, and transactional memory constrain failures. Prompt injection can still affect model interpretation and needs adversarial live-model testing before production.

A hard semantic requirement with no explicit evidence is unknown and cannot qualify. Negated requirements need explicit contrary evidence; missing amenities are not taken as absence. This sacrifices recall to avoid asserting unsupported satisfaction. At most 24 recommendation candidates are checked, in batches of eight; an empty verified set is not called an exhaustive semantic no-match unless review covered the structured pool, and even then missing descriptions remain unknown. Semantic aggregates review at most 80 and report their evidence-limited scope.

No API key is required for deterministic development. Required base dependencies are Streamlit, Pydantic, scikit-learn (and NumPy/SciPy), python-dotenv; pytest is the development test dependency. Optional Ollama supplies local inference and neural embeddings. No paid API use is part of the development or setup scripts.
